# Domain Documentation

Candy currently uses a single product and domain context.

Before changing domain behavior, read these files when they exist:

- `CONTEXT.md`
- `docs/product/candy-v1.md`
- relevant decisions under `docs/adr/`

Create `CONTEXT.md` or an ADR only after a real term, invariant, or architectural decision has been resolved.

Use established Candy terminology consistently. If a proposed change conflicts with an accepted ADR, surface the conflict explicitly.
